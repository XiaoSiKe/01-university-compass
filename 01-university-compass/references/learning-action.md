# 学习与行动卡片

先区分目标：**记住、解释、解题、操作技能、产出作品**。同一课程可有多种目标。来源见 [R08–R15](sources.md)，AI 辅助与独立表现的证据边界补见 [R27](sources.md#r27)。以下步骤与大学案例是 AI 应用设计；研究的平均结果不保证个人效果。

<a id="l01"></a>

## L01：提取与间隔，适合记忆和知识保持

**来源/原观点**：Dunlosky 等（2013，R08）比较十种学习技术，练习测验和分散学习被评为较高效用；Roediger、McDaniel、McDermott（2006，R15）介绍提取与延迟记忆研究。R15是研究者介绍文，不冒充原实验全文。

**问题与条件**：反复看很熟，合上书却想不起。先了解材料、考试要求、已有基础与剩余时间；初学完全不懂时先获得解释和范例。

**方法/提问**：围绕学习目标写少量问题 → 合上资料尝试回答 → 对照可靠答案纠错 → 隔一段时间再次提取 → 根据错误与目标期限调整间隔。不要把固定的“1、3、7天”说成普适最佳间隔。

**应用设计**：护理专业学生学一组课程术语，可先口述含义、核对教材，下一次用新例子辨认。真实临床操作仍遵守课程与专业规范。

**边界**：记忆改善不等于能处理所有新情境；不要只追求刷卡数量。闭卷自测应低风险，错误需要反馈，不能用 AI 未核实答案作为唯一评分标准。

<a id="l02"></a>

## L02：自我解释与有用的笔记

**来源/原观点**：R08 中自我解释被评为中等效用；总结、划线等效用依任务、训练与条件而异，不能据此说笔记毫无价值。

**问题与条件**：觉得看懂了却讲不清“为什么”。先了解要理解的关系、前置知识和可核对材料。

**方法**：读短段或一道解答 → 用自己的话解释因果与步骤 → 标记“我不知道为什么” → 对照原文、教师或可靠解答 → 写成下次能回答的问题。笔记保存来源、关键关系和疑问，少量即可。

**应用设计**：历史专业读论文后写作者主张、证据、可能反例，各一两句；随后不看笔记口头解释它们之间的关系。

**边界**：听起来流畅不等于解释正确。新手可能生成错误解释，应获得纠正；漂亮笔记和长篇复述都不是掌握标准。深阅读和原文细读不能完全由摘要替代。

<a id="l03"></a>

## L03：例题、独立练习与迁移检查

**来源/原观点**：Sweller & Cooper（1985，R09）研究代数例题学习与图式获得，结果对相似题较明确，推广到不同任务须检验；不是所有学科都只需照抄例题。

**问题与条件**：解题时毫无头绪，或会照抄却不会换题。先了解基础、任务相似程度与反馈来源。

**方法**：选一个水平合适的完整示例 → 解释每步为何能做 → 隐去部分步骤补全 → 独立做近似题 → 再做有变化的题并查错。支持逐步减少是本 Skill 的教学应用，不伪称该论文单独验证了此完整流程。

**应用设计**：高数学生先解释一个分部积分例题中如何选项，再独立做相近题，最后判断一道题是否适用分部积分。

**边界**：若错在先备概念，回补概念；若已熟练，增加独立变化练习。模仿成功不证明迁移，不能无限看例题逃避独立尝试。

<a id="l04"></a>

## L04：有支持的问题学习与项目实践

**来源/原观点**：Hmelo-Silver（2004，R10）综述问题驱动学习：围绕复杂问题识别知识缺口、自主学习、应用和反思，辅导者提供支持。该综述对合作与内在动机的证据较少，研究多集中医学与资优教育。

**问题与条件**：想通过项目学东西，却被空泛任务压住。先了解学习目标、基础、时间、合作与指导条件。

**方法**：选真实且有限的问题 → 明确可交付结果与需要学会的能力 → 找出知识缺口 → 获得范例/教师/同伴支持 → 做一个可评估的版本 → 回看哪些知识能独立使用。

**应用设计**：师范学生用一段试讲检验能否解释某概念，按明确标准收反馈再修改；计算机学生则可做一个小功能并解释关键实现。

**边界**：问题驱动学习与项目驱动学习不完全相同；完成作品不自动证明学习，组员或 AI 可掩盖个人缺口。不能把无指导地摸索说成必然优于课程学习。

## L05：元认知校准与学习循环

**来源/原观点**：Zimmerman（2002，R11）把自我调节描述为预先思考、执行、自我反思的循环；Dunlosky & Rawson（2012，R12）作者摘要提示不准确的掌握判断可能损害学习与保持。R12仅摘要，不能引用未读方法细节或精确效应。

**AI 场景的补充证据**：Bastani 等（2025，R27）在土耳其一所高中、使用 2023 年 GPT-4 的数学短期试验中，区分辅助练习与撤去辅助后的考试。普通聊天辅助的练习表现提高，独立考试表现却下降；定制 Tutor 缓解了这一负面影响，但未显示独立考试显著优于无 AI 组。该结果支持分别检查受助表现与独立表现，不证明本 Skill 有效，也不能直接推到大学、所有学科或长期学习。

**问题与条件**：接触过、看懂了、能独立使用混在一起。先把“学会”写成可观察表现，以及可靠的评价标准。

**方法**：选一个具体目标 → 在帮助较少的情况下做基线尝试 → 对比自己预估与实际 → 找关键错误 → 换策略/材料 → 在新题或延迟后再测。允许主动求助，独立学习不等于孤立学习。

**应用设计**：学生跟着 AI 跑通一个程序后，关掉参考独立修改一个小功能，解释输入输出，并用样例检查；记录哪一步仍依赖提示。

**边界**：一次测验不是人格或智力评价；评价标准本身可能有问题，需与教师要求核对。复盘要能改变下一步，避免记录成本超过学习收益。

## L06：按真实容量安排时间

**来源/原观点**：Aeon、Faber、Panaccio（2021，R13）元分析发现时间管理与表现、福祉有关系，多数研究为横断面，不能把相关一概说成因果。可用资源和社会条件影响安排能力。

**问题与条件**：计划很满但执行不了。先了解固定课程、工作/照护、通勤、休息和可支配精力；不预设人人有完整晚间与周末。

**方法**：轻量记录一个有代表性的时间段 → 固定承诺与生活需要先占位 → 按后果、价值和依赖排少量重点 → 留出真实缓冲 → 比较计划与实际 → 删减、协商或调整。长期方向只用来判断近期投入是否值得。

**应用设计**：需兼职的大二学生每周仅有三小时自主学习，可先为最影响学分的内容分两次练习，其余项目暂缓；缓冲和休息按本人条件确认。

**边界**：不以更早起床、压缩睡眠或精细计时作为默认解法；时间表不能解决收入不足、疾病或不合理任务量。效率提升不是唯一目标。

<a id="l07"></a>

## L07：把意愿接到具体情境

**来源/原观点**：Gollwitzer & Sheeran（2006，R14）实施意图元分析及作者解释材料，将可识别的情境与目标行为连接。效果取决于目标认同、情境与行为是否合适，非万能承诺。

**问题与条件**：知道想做什么，但常错过启动机会。先确认目标仍认可、资源可用、动作足够清楚。

**方法**：挑一个实际会遇到的提示情境 → 写“当……，我就……” → 明确可见完成标准 → 预想主要障碍与替代动作 → 试一次，检查失败位置。

**应用设计**：学生认可阅读任务，可拟定“周三午饭后到图书馆坐下，先读摘要并写一个问题；若位置难找，就在已确定的备用地点完成这一步”。时间地点必须符合学生已知条件，未确认的仅作提议。

**边界**：目标不认同、疲惫或材料缺失时，先解决对应问题。五分钟和番茄钟只是可选安排，不能声称研究规定人人应如此。

## L08：小试验、机会成本和失败复盘

**来源/性质**：本 Skill 的 AI 整合设计，受 P01/P03 的探究方法、R11 的循环与 R14 的行动研究启发；不是某篇论文已验证的统一模型。

**问题与条件**：想探索方向但担心投入过大；之前计划没有完成。先了解最重要未知、可承受成本、决定时限与失败后果。

**步骤**：说明待验证判断 → 选择能改变判断的证据 → 设成本上限与结束点 → 行动后记实际发生了什么 → 区分方法、环境、资源与目标的影响 → 继续、修改或停止。别只比较收益，也比较放弃了什么。

**应用设计**：想参加竞赛但已有必修课压力，可先看正式规则和一份往届任务，估计最低工作量；若超出可用时间就不报名或只做旁观学习。没有报名也可以是合理结果。

**边界**：试验需有代表性，不用一次短体验判断终身职业；不可逆选择优先查正式规则与咨询。行动失败本身也是信息，但不代表所有失败都值得重复。


## 在 AI 学习任务中使用这些方法

优先按 [AI 路径](ai-pathways.md) 选择起点，再从 [任务卡](ai-practice.md) 找一项能检验当前问题的活动。本节是上述研究与教程机制的原创应用，不代表某研究验证了整套流程。

- **利用已有起点：** 用户只想听懂概念或完全陌生时先讲解、示范，不先安排基线题；有尝试或明确卡点时直接接着处理。希望检查掌握时，才选一个关键步骤试做，避免为测评重新出一套题。
- **按错误给支持：** 缺概念就解释；缺步骤就演示一个完整例子；会跟做就减少提示；只记住表面形式就改变条件。不要始终反问，也不要以一段长讲解替代学生的下一次尝试。
- **分别验收：** 成果记录可核实的效果和失败边界；学习记录学生实际解释、修改、核对和迁移的表现。AI 完成的部分不能自动成为学生的能力证据。
- **把反馈接到下一步：** 不会第一步时降跨度；当时会而隔天忘时做延迟提取；换任务失败时检查适用条件；做得出但无人需要时回到需求；不再认同目标时回到选择流程。
- **保持可达：** 限额用尽可分析预制答案、补输入材料或设计检查；无法运行代码时可预测输出并解释。记录这些练习的范围，待工具可用再核验运行，不冒称已经部署或运行成功。

技术初学者需要命令时，解释用途、关键参数和成功表现；只介绍当前用到的内容。一次练习难度和长度服从时间、设备与实际表现，不固定每轮一个动作，也不固定必须学完某本课。

讲解、一起做与独立检查是不同支持方式。初次解释可以在一个例子中把过程讲完整，再留给学生消化；不必立即接考试。用户愿意尝试或需要验收时再做小检查。回答正确的部分具体指出，错误的部分用更贴近已有知识的说法处理；减少格式、重复复述和无关追问，不减少必要依据。


<a id="teaching"></a>

### 讲解与检验分开

学生需要解释时可以充分示范；随后要判断独立理解时，换一个关键条件、问题表示或适用情境，不只把刚讲完的答案改几个数字再问一次。独立检验出题当轮不同时给参考答案、解法、正确选项、答案所依赖的原句或指向结论的提示；等学生作答后再核对并讲解。题目本身需要的数据、规则和无关的格式帮助可以提供，不把“独立”变成猜谜。若已给过本题答案，它只能用于讲解或跟做，另换一道合适的新题再测。需要提示就给提示，并如实记录帮助程度；学生明确要完整答案时可以解释，不机械拒绝协作。

例如讲过如何算平均数，检查迁移可让学生判断一份缺失数据能否支持结论，并解释还需要什么，而不是立即复述同一个求和算式。检验的变化必须仍在已具备的基础内；不能为了“独立”突然增加陌生知识或把教学变成猜谜。只有即时带提示的回答时，结论停在“在帮助下完成”，延迟和独立迁移保留待验证。

核查任务不预设一定有错。学生依据材料检查后判断某段回答正确，也可以是有效表现；反馈说明查了哪些关键主张与边界，未检查的部分保持未知。成果可靠不自动证明学生掌握，带提示的正确回答也不因随后说“懂了”变成独立证据。当前证据只支持哪一步，就记录到哪一步，再决定继续、补解释或结束。
