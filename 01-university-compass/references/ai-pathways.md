# AI 入门路径：从当前任务开始

本文件是面向大一、非计算机专业及其他 AI 初学者的教学设计。课程线索来自 [R16–R24](sources.md)，学习支持复用 [L01–L08](learning-action.md)；这里的路径、时间示例和任务安排是本 Skill 的原创整合，没有经过学生效果验证。按问题读一节，无需让学生先读完路线图。

入口：[第一次尝试](#start) · [共通基础](#foundation) · [三条路径](#routes) · [四个阶段](#stages) · [按需选材料](#resources)。实际任务见 [T01–T06](ai-practice.md)。

<a id="start"></a>

## 第一次尝试：约 20 分钟，有一个可检查的结果

已有任务就接着做，不重新测年级、专业或兴趣。学生只说“想学 AI”且条件不明时，可以先给下面的起点；只在确实会改变任务时补问条件。时间是示例，可缩到一次五分钟练习或分几次完成。

1. 拿一段自己有权使用、能看懂的课程材料，约 150–300 字。手机和当前可用的聊天界面即可；没有材料时使用 [T01 的内置材料](ai-practice.md#t01)。
2. 学生先用自己的话说材料讲了什么，再让 AI 依据材料出两道理解题，并指出答案对应的原句。暂时不看参考答案，自己回答。
3. 回到原文检查问题是否有答案、AI 是否增加了材料没有的信息；改好一个有问题的地方。
4. 合上材料，解释一个关键关系，或回答一个稍作变化的问题。留下“三行记录”：做了什么、哪一处需要核对、下次还想学什么。

没有额外账号、预算或 API 时，就用本次对话完成；不能运行工具时可检查已有或教师提供的示例输出。这能够练习表达需求、验证与解释，但不能据此认定已会实际安装、调用接口或开发。无需先购买设备、开通服务、加入组织或看完课程。

第一次反馈决定下一步：完全不懂材料就先讲解；会检查但想省去重复工作可走专业应用；希望自己改变功能可走开发；好奇为什么有效、怎样比较方法可尝试研究体验。暂时没有兴趣继续也可以结束，不把一次任务变成人生定向测验。

<a id="foundation"></a>

## 共通基础：遇到时解释，做过后检查

| 当下遇到什么 | 用大白话说明 | 学生可展示的理解 |
|---|---|---|
| “AI”和聊天工具混在一起 | AI 是广泛的一类方法；生成式模型可以根据输入生成内容，产品还可能连接搜索、文件或其他工具。当前是否能联网，要看实际工具能力 | 能说清本次结果来自给定材料、联网检索还是模型生成，未知时承认未知 |
| 模型没有理解任务 | 说明目的、材料、限制和希望看到的结果；需要时给一个例子 | 能修改一条含糊请求，并解释为什么改 |
| 回答自信、听起来正确 | 流畅不证明正确；把可核对的事实、推理和建议分别检查 | 指出一句需要证据的话，找到依据或将其改为待核实 |
| 想把全部材料传进去 | 只提供当前任务必要且有权使用的内容，去掉无关个人信息；课程使用要求以真实规则为准 | 能选出必要片段，说明哪些不需要上传 |
| AI 做完了，自己感觉学会了 | 作品完成和个人掌握分别检查，求助程度可逐步减少 | 能解释、纠错、独立修改或处理变化任务中的一项 |
| 提示词越写越长仍不好 | 先检查任务、材料与评价标准是否清楚，再决定改提示、换方法或停止使用 AI | 能说明一次修改解决了哪个问题，并比较修改前后 |

基础教学参考 R16/R17 的入门框架、R18 的学生学习材料与 R19/R20 的学习支持思路；这些实践材料不等于证明本教学方案有效。涉及技术定义时只讲当前任务需要的部分，研究路线再展开概率、数据、训练和评价。

<a id="routes"></a>

## 三条路径：由目的分流，允许交叉和切换

通识是共用基础，不是一条要全部学完的长课。三条路径没有高低之分，按学生想完成的事选择；已有证据可跳过前置环节。目的与投入不对应时用 [P07](thinking.md#p07) 检查。

| 路径 | 适合的当前目的 | 起点与必要基础 | 第一个可检查成果 | 何时补基础或换路径 |
|---|---|---|---|---|
| 专业应用 | 帮助课程理解、资料核对、表达、设计或重复工作 | 会使用自己的材料，知道本任务怎样才算好；不默认要求编程 | [T01](ai-practice.md#t01) 的自测与纠错，或 [T02](ai-practice.md#t02) 的证据表 | 检查不了专业内容先补该知识；已有明确重复流程再考虑开发 |
| 开发实践 | 自己改变功能、处理数据或制作可运行工具 | 能描述输入输出；按任务补文件、代码执行、变量、条件与函数。能否运行以实际设备为准 | [T04](ai-practice.md#t04) 的小函数、样例检查和一次独立修改 | 基础不会时回到有讲解的完整示例；需外部模型时才了解 API、密钥与成本 |
| 研究探索 | 想理解方法为何有效、比较不同方法并解释局限 | 可先做无代码的比较体验；深入训练和复现再按任务补 Python、线性代数、概率统计与机器学习 | [T05 的研究子练习](ai-practice.md#research-exercise)：小规模评价和局限说明 | 能运行不等于读懂研究；当前问题过大时缩成可比较假设，设备不足时选小数据或给定输出 |

“开发”和“研究”也可结合：先用现成工具做一个比较，发现问题后再实现一小部分。非计算机学生可以深入研究自己的专业如何使用 AI，不必以模型训练作为唯一入口；也不能把学会聊天工具说成已掌握模型研究。

<a id="stages"></a>

## 四个可跳过的阶段

以下是观察进展的检查点，不是固定四周课表。按每周约两小时举例，每次只安排当前阶段的一项任务，并为课程、休息和现实责任留出空间。学生只有半小时就缩小材料与成果，不要求压缩睡眠补进度。

| 阶段 | 什么时候进入 | 当前任务 | 通过什么证据进入下一段 | 卡住时怎样调整 |
|---|---|---|---|---|
| 1. 做成一次可检查的尝试 | 从未有效用过 AI，或只有零散体验 | 用 T01 完成一次提问、回答与核对 | 能指出一个有依据的结果及一个需核查的地方 | 先解释材料，减少问题；无工具用内置示例 |
| 2. 在自己专业里反复使用 | 已能说清需求，想用于实际学习 | 用 T02 检查信息，或将 T01 换成实际课程内容 | 能在新材料中复用方法，并识别什么时候不宜依赖 AI | 查具体错误，区分材料不足、知识缺口与提示问题 |
| 3. 做一个有反馈的小成果 | 已有明确需求和可承受投入 | 专业应用选 T03，开发选 T04，研究选 T05 的研究子练习 | 成果按标准可检查；学生能解释个人贡献、关键选择和未完成部分 | 缩到一个流程；完成却无用时重查需求，允许停止 |
| 4. 自主选择下一个投入 | 有一次成果或相当经验，想决定继续学什么 | 用 T05 做同题角色体验，再以 T06 联系本专业方向；已有体验可直接比较 | 能说明下一段学习的目的、依据、投入上限与仍未知的事 | 补最影响判断的一条证据；无须现在决定职业 |

已做过项目但讲不清实现，可从阶段 3 的掌握检查开始；已有专业能力但不了解工具限制，可只补共通基础的一项。路线切换时保留已能解释和检查的能力，不把之前投入归零。

## 按任务选一份主材料

下表是经过筛选的入口，不是必修书单。实际阅读范围、原始地址与日期以 [来源表](sources.md) 为准；这里只采用已读范围支持的结论。每次给一份主材料、一个目标和一个可检查产物，访问受阻时再给替代方案。

| 来源线索 | 什么时候有用 | 怎样使用，什么先不做 |
|---|---|---|
| R16：Microsoft 生成式 AI 入门 | 需要理解生成式 AI、提示与应用流程 | 选当前任务相关的一节；实现示例可能依赖账号/API，不要求先跑全套 |
| R17：Microsoft AI 入门 | 想区分 AI 范围、传统方法与神经网络等基础 | 选一个概念并解释例子；目录存在不意味着新生需全部通读 |
| R18：Anthropic 学生材料 | 想让 AI 支持学习、保持学生自己的思考 | 采用学习目标、协作与检查思路，学生用自己可访问的工具实践 |
| R19/R20：TuTor 与 AI Tutor | 设计练习、提示与反馈如何配合 | 借鉴教学组织，按具体错误调整帮助；不把项目宣传视为学习效果证据 |
| R21：LLM Universe | 有编程基础，准备理解模型应用流程 | 从一个有限流程进入；知识库应用的前置、接口与费用另核实 |
| R22：HappyLLM | 希望更系统理解语言模型和相关基础 | 配合已有数学/代码能力选段落；缺先备知识先补一处，不要求从训练大模型开始 |
| R23：Hugging Face 课程 | 有相应 Python 和机器学习基础，想继续学模型与工具 | 先读课程前置与当前任务相关章节，运行条件和资源用量逐项核对 |
| R24：Hello Agents | 能做基础应用，明确想理解或构建 Agent | 先理解任务、工具与评价，再选一个流程；初学使用 AI 不必先学 Agent 框架 |

资料无法打开时，用已经提供的材料继续做同一能力练习；不能假称读过未打开的章节。不要凭仓库热度排序教学价值，不把课程免费公开等同于代码运行、接口或部署零成本。涉及安装、产品能力与费用时核对当前正式说明，学生没有要求安装时只提供学习选择。


## 选择工具时的一次短验证

学生要求最新排行、价格或购买建议，而当前不能核实时，明确不能据此选定品牌；未给预算时默认新增支出上限为0。可先用已有工具，不把“首次只买一个月”当作金额预算，也不保证任何服务当前免费。

即使学生不想做长比较，也简短提供一个可选的约五分钟验证动作：拿当前任务中的一小段真实输入，预先写一个能核对的正确结果，检查现有工具能否完成；再问一个材料没有答案的问题，看它会不会补猜。记录结果是否可核查、哪里失败，以及是否真的受额度或必要功能限制。这是可跳过的小检查，不要求试遍多家产品。

没有可用工具时先写输入与判断标准，明确尚未运行；不以纸面设计替代实际结果。确实需要付费时，再核实官方当期价格、学校授权和任务需求，由学生设定可承受的金额上限；未经确认不安排购买或把花费写成已决定。
